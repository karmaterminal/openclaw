## Findings

### 1. HIGH — moved adoption helper leaves the restart/recovery owner uncompilable

`src/auto-reply/continuation/work-terminal-notice.durability.test.ts:35` still imports `settleManagedSystemEventsAfterTurnAdoption` from `../reply/session-system-events.js`, but commit `431868f84bbfef085896677e8a6c970dc4709fa9` moved the export to `src/auto-reply/reply/session-system-event-adoption.ts:88` and removed it from the old module.

This is candidate-owned and deterministic:

- `b8a16fd7` with the original 12-case durability suite: 12 passed.
- `c2ee2f6c` with the same suite: 2 failed / 10 passed with `TypeError: settleManagedSystemEventsAfterTurnAdoption is not a function`.
- Changed-path `tsgo:core:test`: `TS2305`, no exported member at the unchanged import.

The broken cases are the restart/recovery owner proofs that a durable row completes only after turn adoption, stops replaying, and clears a stale work flag against a completed tombstone. This is not a product-runtime failure by itself, but the candidate is not safe to enter the bounded GATES absorb while an existing owner suite and core test typing are red.

Root cause: the helper's architectural ownership moved, but the complete consumer set was not migrated. `git blame` shows the missed consumer predates the candidate; the breaking export removal was authored and committed by `scribe-dandelion-cult` in `431868f84bb` on 2026-08-29. No PR is associated with this six-commit repair stack.

Best fix: update the existing test import to the new adoption-owner module. Do not add a compatibility re-export to production.

I found no production simplification that preserves behavior byte-for-byte. The concrete correction is test-only: migrate the stale restart/recovery import to the new owner. A production compatibility re-export would add redundant surface and is the worse fix.

Alternatives considered:

1. Keep the helper in `session-system-events.ts`: rejected because final adoption now has an independent owner and callers already use it directly.
2. Re-export from the old module: rejected because the old path is internal, unshipped compatibility is not required, and a one-line test import migration is complete.
3. Collapse all authority bindings into one map: rejected because it would reintroduce route/current cross-batch scope aliasing.
