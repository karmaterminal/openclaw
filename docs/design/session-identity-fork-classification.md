# Session identity ratchet: fork-line classification

**Scope:** the `karmaterminal/openclaw` fork line only. This is not an upstream allowlist and not an upstream-clean claim.
**Fork base:** `e2b03395cdb887fb48b4f4d47e7f4b2155cf7ec9`. **Upstream base:** `9122a49bd8a12baf734ec7bb78337bd556fcbef8` (the upstream `main` the fork line absorbed).
**Date:** November 2026.

Upstream's `check:session-identity-ratchet` counts raw session identity use outside the session store: compares on a transcript id, lifecycle revision, run id, generation or leaf id, the `expectedSessionId` and `expectedLifecycleRevision` pin names, and "changed"/"replaced" refusals. It allows only the counts in `config/session-identity-allowlist.txt`, and that file may only shrink. On the fork line, 38 files exceed upstream's allowlist. This page records, for each file, the contract that needs the raw identity and the test that pins it, or the seam that would.

## How the fork base measures the 38 files

The ratchet measures them through its own mechanism, with no allowlist entries for them (line numbers are in `scripts/lib/shrink-ratchet.mts`):

- `--base` resolves to the merge base of `HEAD` and the base (`resolveRatchetBase`, lines 80-111). The fork line descends from `e2b03395`, so that commit is the base.
- `allowanceWithExistingBaseCounts` (lines 346-367), applied to the current counts at lines 430-433, raises a file's allowance to its pin count at the base. Each of the 38 files has the same count at `HEAD` as at `e2b03395`, so each may keep exactly its fork-base count and may only shrink. A path missing at the base gets no allowance (line 363), so a new file with a pin fails.
- The allowlist cannot mark an entry as fork-only. It holds only `path\tcount` lines (`parseRatchetCounts`, lines 213-228), and `--prune` rewrites it without comments (lines 313-319 and 461-468). Adding the 38 files (what `--prune --base e2b03395` writes: 33 new entries and 5 raised counts) would be a 38-file upstream allowlist expansion. At the upstream base it would change the failure to `The session identity allowlist may only shrink:` for the same 38 files (lines 434-441).

The fork line shrinks three upstream entries whose pins it moved verbatim into split files. Before this, `--base e2b03395` reported them as stale:

## Classes

- **custody:** accepted-spawn custody persists the child's transcript id and lifecycle revision, so a restart can stop or delete exactly that child. Deleting by key alone could remove a newer generation (`src/agents/subagents/spawn/subagent-spawn-cleanup.ts:190`). Upstream's public `sessions.delete` takes the same precondition (`packages/gateway-protocol/src/schema/sessions-delete.ts:12-13`, `src/gateway/server-methods/sessions-delete.ts:229-230`).
- **run key:** custody, an election or a child listing belongs to one run: the gateway run, the origin run, the requester turn or the registration.
- **reset fence:** a durable row or trusted event names the transcript it was produced for, so a reset or replacement drops it instead of delivering it into the successor. Upstream's restart agent-turn delivery does the same for its own rows (`src/gateway/server-restart-sentinel-agent-delivery.ts:289` at `9122a49b`, allowlisted at 8).
- **incarnation:** a live precondition that the admitted, source or operator-named incarnation still holds at the point of effect.
- **moved:** upstream's own pin, moved verbatim into a split file.
- **shape:** a `typeof x.runId === "string"` shape guard that the regex counts. Upstream `main` later stopped counting type checks (openclaw/openclaw#200533); under that rule both files count 0.

## Per-file classification

Pins are the counts at `HEAD`, which equal the counts at `e2b03395`. The parenthesis gives upstream's allowance at `9122a49b`: the allowlist entry, or `new file`. A test pin is a test that fails when the check is reduced to a key-only (ChatRef-style) check. "Unpinned" means a key-only mutation left the focused tests green.

- By class: custody 8 (two also run key), run key 9, reset fence 11, incarnation 6, moved 2 (one also run key), shape 2. ## What this does not claim

- It does not make the gate pass at the upstream base, and it does not change the ratchet script, "may only shrink", or any upstream-base behavior.
- The focused suites and mutation pins behind this table support the fork-line classification only. They are not upstream acceptance.
- For an unpinned file, the reason given rests on reading the contract. Its probe shows only that no current test would catch a key-only rewrite there.
